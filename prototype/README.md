# TCM-DOR 知识图谱原型 · 设计说明

> 卵巢储备功能减退（DOR）文献与病案数据平台，四角色纯前端原型。
> 不连接后端、不修改 `UI/frontend`，所有数据来自本地 mock，用于评审信息架构与交互。

**配套文档**

- [事务状态流转模型](docs/state-models.md)：ETL、上传队列、任务池、标注任务、复核条目、用户账号的完整状态机

---

## 1. 项目定位

本原型覆盖 DOR 数据从**上传 → 抽取 → 标注 → 复核 → 入图**的完整链路，重点验证：

- 四类角色看到什么、能做什么
- 数据源、数据管理、标注管理之间的职责边界
- 标注员与复核员的真实工作台交互
- 文献 / 病案双类型任务的统一管理
- 三栏编辑布局、任务卡片、筛选与图谱浏览体验

原型只做前端演示：无鉴权后端、无真实文件上传、无 API 请求、无真实 LLM 抽取。

## 2. 技术栈

| 项 | 选型 |
|---|---|

| 路由 | Vue Router 5，`createWebHistory` |

|---|---|---|---|---|
| 普通用户 | `normal` | `/chat` | 智能问答 | 仅智能问答 |

- 未登录访问业务路由 → `/login`

- `/` 按角色跳转：管理员 `/admin`、标注员 `/annotate`、其他 `/chat`
- 未知路径 → `/login`

侧栏顺序固定：

```

标注员：任务领取 / 标注工作台
专业用户：智能问答 / 智能搜索 / 知识图谱
普通用户：智能问答
```

侧栏支持折叠为 64px 图标栏；用户信息卡片与「切换角色」始终贴底。

### 5.1 路由访问说明

- 未登录直接打开业务页面 → 跳转 `/login?redirect=<原路径>`
- 当前角色无权访问 → 同样跳转登录页，并提示选择对应角色
- 在登录页选择正确角色后，会**自动回到原页面**，不再固定回角色首页
- Nginx 静态部署必须配置 SPA 回退，否则直接刷新子路由会 404：
  `try_files $uri $uri/ /index.html;`
- 部署后部分页面白屏 / 资源 404，通常是使用了旧 `dist`，重新 `npm run build` 并完整替换 `dist` 即可

## 6. 全局设计规范

### 6.1 页面结构

- **不显示页面级标题**，内容直接进入统计卡、页签或工具栏
- 页签下划线统一：左右各 10px、2px 高、`2px 2px 0 0` 圆角
- 表头浅灰、行悬浮浅色、操作按钮紧凑
- 提示性文案保持克制，避免重复说明

### 6.2 控件高度

| 控件 | 高度 |
|---|---|
| 页头主按钮（建池向导等） | 32px |
| 筛选下拉 / 搜索框 / 上传按钮 | 33px |
| 普通按钮 | 按内容自适应 |

### 6.3 类型色

| 类型 | 颜色 | 使用位置 |
|---|---|---|
| 文献 | 青绿 `#00796b` | 任务卡片、任务列表边框、文献徽标 |
| 病案 | 琥珀 `#b06a00` | 任务卡片、任务列表边框、病案徽标 |

标注工作台与复核队列中：

- 所有任务卡片直接显示所属类型色边框
- 当前任务用同色描边高亮
- 左侧任务列表边框随当前任务类型切换
- 列表收起后的窄条保留类型色（3px 左边框）

### 6.4 三栏编辑布局

适用于：

1. 数据管理 · 全屏编辑
2. 标注管理 · 复核详情
3. 标注工作台

展开状态：

```
任务列表 : 原文 : 编辑框 = 1 : 2 : 2
```

收起任务列表后（窄条 26px）：

```
原文 : 编辑框 = 3 : 2
```

实现方式：

- 使用 CSS `calc` 扣除固定间距与 7px 拖拽条
- 原文与编辑框之间保留拖拽条，可自定义宽度
- 收起 / 展开时重置为约定比例
- 1280 / 1600 宽度下均保持比例

实测（1600）：

| 布局 | 展开 | 收起后 |
|---|---|---|
| 标注工作台 | 252 : 504 : 504 | 741 : 494 |
| 复核详情 | 253 : 507 : 507 | 745 : 496 |
| 数据管理编辑 | 308 : 616 : 616 | 908 : 605 |

## 7. 页面设计

### 7.1 登录页

- 四张角色卡片，左侧角色色条
- 点击角色写入 localStorage 并进入对应首页
- 登录页保留产品品牌标题，业务页面不显示标题

### 7.2 智能问答

- 共享 `chatStore`，对话历史持久化
- 消息支持 AI / 用户气泡、引用文献 chips、时间与角色标签
- 输入框 + 发送按钮，发送中显示打字动画
- 侧栏「开启新对话」为整宽圆角矩形按钮，无「对话历史」文字
- 会话按「今天 / 昨天 / 更早」分组
- 支持新建、切换、删除会话

### 7.3 智能搜索

- 先搜索、后筛选：搜索前筛选面板隐藏，搜索后出现在左侧（参考知网）
- 筛选维度：来源类别（文献 / 病案）、研究类型、证型、年度
- 筛选计数基于当前关键词命中结果统计
- 结果卡片展示类型、编号、标题、作者 / 年龄、研究类型、证型、更新时间、命中字段
- 右侧抽屉查看完整字段分组

### 7.4 知识图谱

- 顶部独立行展示实体数量 / 关系数量
- 边类型筛选栏为内容宽度，支持 7 类关系开关
- 左侧图例：6 类节点、7 类边
- 中间 SVG 画布：节点、边、网格、选中态
- 右侧实体详情：类型、关联边、属性
- 底部图谱范围与节点 / 边统计

节点类型：文献、病案、关键词、药物、方剂、证型。

边类型：`ref`、`similar`、`MENTIONS`、`CONTAINS`、`TREATS`、`HAS_OUTCOME`、`CO_OCCURS`。

### 7.5 任务领取

- 统计卡：可领取文献、可领取病案、我的进行中任务、返工任务
- 可领取任务按每批 5 条生成卡片
- 领取后进入「我的任务」，状态含待标注 / 标注中 / 返工中
- 「去标注」跳转 `/annotate/workbench`
- 页面不显示「前往标注工作台」按钮

### 7.6 标注工作台

页签：

```
标注任务 / 返工箱 / 我的标注记录
```

**标注任务**

- 顶部横向任务卡片，支持左右箭头、滚轮横滑、点击切换
- 卡片信息：任务号、状态、条目数、已处理数、截止日期
- 卡片边框按文献 / 病案着色，当前任务同色高亮
- 工作区三栏：任务条目 | 原文 | 字段编辑
- 条目列表可收起为 26px 窄条，窄条保留类型色
- 原文支持小 / 中 / 大字号
- 病案额外显示关键字段 chips（年龄、AMH、证型等）
- 字段按母版前 2 组渲染，长字段自动占整行
- 底部操作：标记无需修改、暂存本条、提交整批
- 提交弹窗显示暂存条数，提交后任务进入待复核

**返工箱**

- 展示复核驳回任务：任务号、类型、条目数、驳回时间
- 支持「返工完成并重新提交」

**我的标注记录**

- 展示近 30 天提交记录：编号、对象类型、标题、状态、提交时间、复核意见

### 7.7 平台总览

- 6 张核心指标卡：文献、病案、标注员、待复核、图谱节点、图谱边
- 最近动态时间线：建池、派发、复核通过、抽取失败、回滚、新增用户
- 待办面板：待复核、抽取失败、近似实体裁决
- 不显示「数据截至」时间戳

### 7.8 数据源管理

父级页签：

```
资源管理 / 基础配置
```

**资源管理**

- 上传文件、上传队列（队列上限 10，逐文件设置文献 / 病案）
- 筛选：批量操作、状态、类型、关键词
- 批量操作四项：
  - 删除（确认弹窗）
  - 设置（弹窗选择文献 / 病案）
  - 抽取
  - 取消抽取
- 表格列：文档、类型、状态、置信度、失败原因、上传时间、操作
- 行操作：抽取 / 取消抽取 / 详情 / 删除
- 列表仅展示四态：待抽取、抽取中、抽取失败、已完成
- 分页 10 / 20 / 50 / 100

**基础配置**

- Prompt 模板：按研究类型维护版本、更新时间、状态
- 枚举词典：证型、方剂、药物等词条增删
- 校验阈值：最低置信度、必填缺失策略、单位异常策略、并发数
- 模型参数：模型名、temperature、maxTokens、timeout
- 编辑即自动保存到 localStorage，无保存按钮

### 7.9 数据管理

- 页签：文献库 / 病案库，同一页面切换
- 工具栏：关键词搜索、研究类型、证型、状态筛选、分页

- 点击「编辑」进入全屏三栏编辑器：

  - 原文
  - 字段编辑
- 顶部栏：记录信息、置信度、取消、保存
- 字段按母版分组渲染，必填标记、下拉枚举、长文本

## 8. 核心业务流程

### 8.1 ETL 状态机

```
pending → extracting → review → validated → graphed
                 ↘ failed →（重试）extracting
review →（退回）pending
validated →（退回）review
graphed →（重抽）pending
```

| 状态 | 含义 |
|---|---|
| `pending` | 待抽取 |
| `extracting` | 抽取中 |
| `failed` | 抽取失败 |
| `review` | 待校验 / 可进入标注 |
| `validated` | 待入图 |
| `graphed` | 已完成 / 已入图 |
| `ignored` | 已忽略 |

原型中标注流程主要使用 `review → graphed`。

### 8.2 标注任务生命周期

```
assigned（待标注）
  → drafting（标注中）
  → submitted（待复核）
  → approved（已通过，文档入图）
  ↘ rework（驳回，进入返工箱）
      → submitted（重新提交）
```

- 管理员建池 → 指派文档 → 标注员领取
- 标注员暂存 / 标记无需修改 → 提交整批
- 复核员通过 → `annotationStore.approve` 将文档置为 `graphed`
- 复核员驳回 → 任务进入 `rework`

### 8.3 复核规则

- 仅比较本次提交发生变更的字段
- 变更字段琥珀高亮，显示「原值 → 提交值」
- 通过：变更合入母版，文档入图
- 驳回：退回标注员修改，任务进入返工箱
- 复核详情不显示任务信息头与说明提示，直接进入三栏比对

### 8.4 数据源到入图

```
上传文件 / 上传队列
  → 资源管理（待抽取）
  → 抽取中
  → 抽取成功（review）
  → 管理员建池
  → 标注员领取 / 标注
  → 提交复核
  → 通过入图（graphed）
```

## 9. 数据模型

### 9.1 文档（etlStore）

```js
{
  id, name, kind,          // kind: lit | case
  state,                   // pending | extracting | failed | review | validated | graphed | ignored
  confidence,
  values,                  // 字段键值
  errors,                  // [{ code, field, message }]
  version,
  uploadedAt,
  operator,
  history,                 // [{ at, action, by }]
}
```

### 9.2 标注任务（annotationStore）

```js
{
  id, kind,                // lit | case
  assignee,
  status,                  // assigned | drafting | rework | submitted | approved
  docIds,
  createdAt,
  rejectedAt,
  deadline,
}
```

### 9.3 字段母版

| 类型 | 字段数 | 分组数 |
|---|---|---|
| 文献库 | 65 | 8 |
| 病案库 | 41 | 8 |

字段来源：`src/constants/dorFields.js`，包含必填标记、下拉枚举、字段描述。

### 9.4 Mock 数据

- 文献 20 条 + 病案 20 条，共 40 份 ETL 文档
- ETL 状态分布：待抽取 8、抽取中 3、失败 5、待校验 16、已入图 6、已忽略 2
- 初始标注任务 8 个：
  - 5 个待标注
  - 1 个标注中
  - 1 个待复核
  - 1 个返工
- 任务池 4 个
- 复核任务 8 个
- 用户 10 个
- 图谱 mock：14 个节点、12 条边

### 9.5 localStorage 键

## 11. 云服务器部署

Vite 已配置监听 `0.0.0.0`，可通过公网 IP / 域名访问；云服务器安全组需放行对应端口。

### 方式一：直接运行（快速验证）

```bash
cd prototype
npm ci
npm run dev -- --host 0.0.0.0 --port 5600
```

访问 `http://<服务器公网IP>:5600`。

生产构建预览：

```bash
npm run build
npm run preview -- --host 0.0.0.0 --port 5601
```

访问 `http://<服务器公网IP>:5601`。安全组放行 `5600` 或 `5601`。

### 方式二：Nginx 静态部署（推荐）

```bash
cd prototype
npm ci
npm run build

sudo mkdir -p /var/www/tcm-dor-prototype
sudo cp -r dist/* /var/www/tcm-dor-prototype/
sudo cp deploy/nginx.conf /etc/nginx/conf.d/tcm-dor.conf
sudo nginx -t
sudo systemctl reload nginx
```

访问 `http://<服务器公网IP>`。安全组放行 `80`；HTTPS 再放行 `443`。

> 前端使用 `createWebHistory`，Nginx 必须配置 `try_files $uri $uri/ /index.html;` 作为 SPA 回退，否则刷新子路由会 404。

## 12. 原型边界

- 无后端、无真实鉴权、无 API 请求
- 文件上传仅记录文件名与大小，不真正上传
- 抽取、复核、入图均为前端状态流转
- 对话、图谱、统计卡为 mock 数据
- 数据仅保存在当前浏览器 localStorage
- 不做移动端适配，目标桌面宽度 1280 / 1600
- 原型不修改现有 `UI/frontend`
